## Context

A telecom operator runs its B2B ordering on a legacy Conceptwave-based stack.
The order flow crosses many downstream systems, change windows are regulated,
and the business can't stop taking orders while the platform underneath it is
replaced. The move happens one service line at a time, over several years,
until Conceptwave can be retired.

I lead both teams: the transformation team building the new platform, and the
Conceptwave team that keeps the legacy system running through the transition.

## The path of an order

The new platform covers the full order flow, modeled on TM Forum Open APIs and
integrated with the operator's downstream systems.

## What I built

**The foundation.** I set up the platform the team builds on: the repository
and the structure of every service, the implementation templates, the shared
building blocks for logging, caching, migrations and API clients, the API
gateway, and the .NET Aspire environment the whole team develops and runs the
system in.

**The modules on top of it.** I contribute across all of them: order
management (quote, decomposition into product orders, discounts), the order
entry UI and the task framework its screens run on, the product catalog and
the utility services.

## Decisions

**Build on reusable assets.** Catalog, ordering, workflow and integration
components are shared, so each new service line builds on the same foundation
instead of starting over.

**Move in phases, side by side.** Each service line is cut over on its own.
Both systems run in parallel, and the new platform has to show it behaves like
the old one before the switch, inside the regulated change window.

**One way of working for both teams.** Implementation templates, code review,
unit testing and quality standards are the same on the new platform and on the
legacy side, and I mentor the developers on both teams.

## Outcome

Cut-overs ship on schedule without disrupting live order flows. Each new
service line starts from the shared assets rather than from scratch, and the
legacy system stays stable for the business until its last service line moves
over.
