A submitted quote doesn't become one big transaction. It is decomposed into
product orders, and each product order runs as its own Camunda process. The
process creates the service orders that deliver the product, then waits:
downstream systems answer asynchronously through callbacks, and the steps that
need a person become user tasks.

Modelling it this way means every order has a name, a state and a history,
and a question like "can this still be cancelled?" has a precise answer. Before
the milestone, a cancel request stops the process cleanly. After it, the
request is rejected, because work downstream can no longer be taken back.

The flow is generic: the shape of a real order platform, none of its names.
